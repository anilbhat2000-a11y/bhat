3C ITS VisionOps Installation Guide

This guide takes you from a bare Linux server to a running multi-organization system. By the end you will have organizations, branches and offices set up, cameras and NVRs onboarded, alert contacts receiving notifications, and health dashboards live. Every screenshot was captured from a fresh install of this version.

Time needed: about 45 minutesSkill level: basic Linux command lineInternet: needed only to download packages
About the screenshots The devices in these screenshots use the simulator health driver, so the dashboards show realistic numbers without real hardware. That is why a SIMULATED DATA badge appears at the top right. For your real cameras and NVRs, choose the generic camera driver and the tcp, onvif or hikvision_isapi NVR driver (step 8).

01Requirements

02Install

Option A: Python (recommended for a first install)

  1. Get the code and go into the project folder: 
    git clone https://github.com/anilbhat2000-a11y/bhat.git
cd bhat/sentinelcore
  2. Create a virtual environment and install the pinned packages: 
    python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
  3. Run the test suite to confirm the install works on this machine: 
    pytest -q
    .........................................................................[100%]
73 passed
Folder and command namesThe product is called 3C ITS VisionOps. Its code folder is still sentinelcore, the Python package is sentinel (as in sentinel.main:app), and settings start with SC_. Keep using these names in commands.

Windows: start and stop with a double-click

On Windows, don't start VisionOps by typing the command into PowerShell. Use the launcher in the sentinelcore folder instead:

FileWhat it does
start-visionops.batStarts VisionOps and opens it in your browser. If it is already running, it just opens the browser.
stop-visionops.batStops VisionOps.

Why: a server typed into a PowerShell window pauses as soon as someone clicks inside that window (Windows' QuickEdit mode). It also stops when the window closes. The launcher avoids both:

  • It runs VisionOps in the background, separate from the window, with its messages written to log files in the logs folder (rotated automatically, so they never fill the disk).
  • It checks VisionOps every 5 seconds and restarts it if it stops or stops answering.
  • Before starting, it checks Python, the packages, the port and the folder, and says in plain words what to fix. It installs missing packages by itself, and repairs the SQLAlchemy block described below.
  • On first start it creates visionops.env with your settings: secret key, admin password, demo data, address and port. Edit that file instead of typing settings each time.

To start VisionOps automatically when you sign in to Windows, run this once in the sentinelcore folder (undo with --remove-autostart):

python -m sentinel.launcher --install-autostart

Other launcher commands: --status (is it running?), --check (run the checks only), --stop.

Tested on Linux, not yet on WindowsThe launcher's start, watch, restart and stop logic is covered by automated tests. The two .bat files and the Windows-specific parts (background start, sign-in start) have not yet been run on a Windows PC. If one misbehaves, send logs\server-output.log to support.

Windows notes for a manual start

Only needed if you don't use the launcher:

  • Open PowerShell as a normal window, not “Run as administrator”, and work in your own folder (cd $env:USERPROFILE). C:\Windows\system32 is protected.
  • Start with python -m uvicorn rather than uvicorn. Settings are read from visionops.env if it exists.
  • Don't click inside the PowerShell window while the portal runs. If the portal seems frozen, press Enter in that window.
python -m uvicorn sentinel.main:app --port 8080

If Windows says “An Application Control policy has blocked this file” (Smart App Control or a company policy):

  1. Use python -m pip instead of pip, and install into Python's own folder (skip .venv): python -m pip install -r requirements.txt.
  2. If the block mentions SQLAlchemy (_collections_cy, _result_cy), install its pure-Python version, which contains no program files to block: 
    python -m pip uninstall -y sqlalchemy
python -m pip install setuptools wheel
$env:DISABLE_SQLALCHEMY_CEXT="1"; python -m pip install --no-binary sqlalchemy --no-build-isolation --no-cache-dir "SQLAlchemy==2.1.9"
  3. If another component is blocked, ask IT to allow Python's packages, or run the portal on an Ubuntu server or VM.

Option B: Docker Compose with PostgreSQL

cd bhat/sentinelcore
cp .env.example .env      # fill in SC_SECRET_KEY, SC_ADMIN_PASSWORD, POSTGRES_PASSWORD (and SMTP/SMS if wanted)
docker compose up -d
Not yet testedThe Docker image has not been built yet. The app itself is tested on PostgreSQL 16. If the build fails, use Option A with SC_DATABASE_URL pointing at your PostgreSQL server (step 20).
Upgrading from v0.1The database layout changed in v0.2 (organizations and the location tree). There is no upgrade tool yet, so start with a new, empty database.

03First start and sign-in

Create a secret key once and keep it safe. It signs logins and encrypts the camera and NVR passwords stored in the database.

python3 -c "import secrets; print(secrets.token_urlsafe(48))"
SC_SECRET_KEY='paste-your-key-here' uvicorn sentinel.main:app --host 0.0.0.0 --port 8080

On the first start, 3C ITS VisionOps creates the platform administrator admin and prints its password once:

To choose the password yourself, add SC_ADMIN_PASSWORD='…' before uvicorn. Then open http://<server-ip>:8080. The landing page opens; choose Sign in.

Add your company logo

Save your logo as a PNG file named logo.png in sentinelcore/sentinel/static/, then refresh the browser. It appears on the sign-in screen and at the top left of every page (in the header on phones), on a white panel so it reads in both light and dark themes. A wide logo works best, for example 2000 × 880 pixels. Until the file is there, the portal shows the name “3C ITS VisionOps” in text.

Just evaluating? Start with SC_SEED_DEMO=1 to get two sample organizations with branches, 6 NVRs, 48 cameras, alert contacts, and demo users (password Demo@12345).

04Create an organization

Each customer or company is an organization. Its locations, devices, users, alert contacts and audit log are completely separate from every other organization. Only the platform admin sees all of them.

  1. Open Organizations.
  2. Enter the name and a short code, for example ACME.
  3. Name its top-level location. This is usually “Corporate Office”.
  4. Choose whether device changes need approval (step 16).

05Build the location tree

Name every place where cameras and NVRs are installed, in the organization's own hierarchy. For example: Corporate Office › West Region › Mumbai Andheri Branch › 2nd Floor › Server Room. Cameras and NVRs can be placed at any level.

  1. Open Locations.
  2. Choose Add under next to the parent location.
  3. Enter the name and pick the type: region, branch, office, warehouse, store, plant, building, floor or area.
  4. Optionally add a short code (useful in CSV imports) and the city.
  5. Add the latitude and longitude so its cameras appear on the Camera map (step 15). Locations under it (floors, areas) use the same position unless they have their own. You can copy the numbers from any map app by right-clicking the building.
Branch is worked out for youA camera on “2nd Floor” is reported under “Mumbai Andheri Branch” on the dashboards. 3C ITS VisionOps uses the nearest branch, office, warehouse, store or plant above the camera.

06Add users and set access

Access follows the hierarchy. A user assigned to a location sees and manages that location and everything under it.

RoleSeesCan do
Super adminAll organizationsEverything; creates organizations and alert rules
Org adminWhole organizationDevices, locations, users, contacts, approvals, reboot, troubleshoot
Location adminAssigned locations and belowSame as org admin within scope; creates users with lower roles only
OperatorAssigned locations and belowAcknowledge alerts, mark AI events true or false
ViewerAssigned locations and belowView only
AuditorWhole organizationView only, plus the audit log

07Add alert contacts

Alert contacts are the people who are told when something goes wrong. They do not need a login.

  1. Open Alert contacts.
  2. Enter the name, designation, mobile number (with country code) and email.
  3. Choose the location. A contact gets alerts for that location and everything under it.
  4. Choose:
    • Send by: email, SMS or both.
    • Which alerts: critical only, warning and critical, or all.
    • For: cameras, NVRs or both.
    • When: immediately, or as an escalation 15, 30, 60 or 240 minutes later if nobody has acknowledged the alert.
  5. Use Send test to confirm the message arrives.

Turn on email and SMS

Add these to the server's environment (step 20). Until they are set, the Notification log shows each message as skipped, so nothing is lost silently.

SC_SMTP_HOST=mail.yourcompany.com
SC_SMTP_PORT=587
SC_SMTP_USER=sentinel@yourcompany.com
SC_SMTP_PASSWORD=your-mail-password
SC_SMTP_FROM=sentinel@yourcompany.com
SC_PUBLIC_URL=https://sentinel.yourcompany.com

# SMS: any HTTP gateway. {phone} and {message} are filled in for you.
SC_SMS_URL=https://your-sms-provider.example/api/send
SC_SMS_BODY={"to": "{phone}", "text": "{message}"}
SC_SMS_HEADERS={"Authorization": "Bearer your-api-key"}
Check your SMS provider's formatEach provider names its fields differently. Copy the request format from your provider's API documentation into SC_SMS_URL, SC_SMS_BODY and SC_SMS_HEADERS, then use Send test.

08Add NVRs and import their channels

  1. Go to Manage devices → NVRs → Add NVR.
  2. Enter its name, location, department, make, model, IP address, ports, channel count and login.
  3. Choose the health driver:
    • tcp: checks the NVR answers. Works with any brand.
    • onvif: also reads make, model, serial number and firmware.
    • hikvision_isapi: also reads disk status and storage. Test it on your model first (step 22).

After saving, the Import NVR channels tab opens. Enter the channels (for example 1-8, or blank for all). One camera is created per channel, with its stream address filled in and the NVR's location and department copied over.

MakeMain stream address created
Hikvisionrtsp://{host}:554/Streaming/Channels/{ch}01 (sub stream …{ch}02)
Dahua / CP Plusrtsp://{host}:554/cam/realmonitor?channel={ch}&subtype=0
Any other brandType your own template using {host}, {port} and {ch}

09Bulk import cameras from CSV

Open Manage devices → Bulk CSV import, choose Download template, fill in one row per camera, then Validate and Import.

ColumnAllowed values
locationA location code (PUN-WH), the full path (Corporate Office / West Region / Pune Warehouse), or a name that is unique. If a name matches more than one location, the row is rejected and you are asked for the code or path
departmentFree text, for example Security, Finance or Logistics
rtsp_url, sub_stream_urlMust start with rtsp://
power_typepoe, mains, battery or solar
drivergeneric (full check), rtsp (only checks the camera answers) or simulator

10Add a single camera

Manage devices → Cameras → Add camera. Make, model and serial number are read from the camera automatically when it is reachable over ONVIF, so you can leave them blank.

11Find cameras automatically (ONVIF)

Manage devices → ONVIF discovery asks every ONVIF camera on the server's own network segment to identify itself. Choose Add next to a result to open a pre-filled Add camera form.

Discovery does not cross routersMulticast stays inside one VLAN. For other VLANs and branches, give the server an interface there or use CSV import.

12Manage devices

Manage devices is where cameras and NVRs are added, edited, activated or deactivated, rebooted and deleted. Each row shows location, department, make, model, serial number, NVR and channel, state, and the error message when a device is not working.

Device details

Troubleshoot

Troubleshoot runs these checks in order and shows a fix for anything that fails:

  • network reachability to each port
  • the RTSP video service
  • the ONVIF clock and login (make, model, serial)
  • the video stream (codec, resolution, FPS, bitrate)
  • a picture check (dark, blank, blurred)

Reboot

Test reboot on one device firstRemote reboot follows the published ONVIF and Hikvision specifications but has not yet been tried on real hardware. Try it on one camera and one NVR during a maintenance window.
Deactivate instead of deleteA deactivated device keeps its history but is no longer checked and raises no alerts. Its open alerts are closed. Use it for cameras under repair or seasonal sites.

13AI use cases

The Use cases page holds the catalog of AI use cases for 13 sectors, from cross-industry to airports, grouped into 12 categories. Examples: two custodians at the vault, a forklift too close to a person, a phone in a no-device bay, tailgating, a queue that is too long. The catalog has 184 built-in use cases, covering every example in the requirement list, and you can import the rest of your own list.

Step 1: tell the portal which models and integrations you have

Many use cases need a specialised AI model (face, number plates, pose, PPE, ATM tamper…) or data from another system (POS bills, token queue, roster, badge events). On Models & integrations, the platform admin marks each one installed once it really runs on your edge boxes or GPU server and has been tested on your own footage.

Step 2: see what is available

StatusMeaning
AvailableEverything it needs is installed. Rule-based ones can be set up on any camera now
Needs modelA specialised AI model must be installed and tested first
Needs integrationData from another system (POS, token queue, roster, badge events…) must be connected first

Step 3: switch a use case on for a camera

  1. Open a camera and choose Add use case, or use Set up on camera on the Use cases page.
  2. Pick the use case and the camera.
  3. Adjust its settings: for example, alert after how many seconds, the minimum number of people, or the safe distance.
  4. Click on the picture to draw the zone (at least 3 points) or the line (2 points). Leave it empty to use the whole picture. When the camera can send a still image, it is shown behind the grid.

The edge box or GPU server for that location picks up the camera's use cases from the portal automatically (step 18). Events then appear on AI events under the use case's own name. They are counted by category on the overview and go to the location's alert contacts.

Rule types available for your own use cases

RuleTypical use
Object in a zoneIntrusion, phone in a secure bay, person on the tracks
Crossing a line / countingVirtual fence, wrong way, footfall
Staying too longLoitering, illegal parking

Import your full use-case list

The platform admin can add use cases from a CSV file at the bottom of the Use cases page. Download the template first. Each row needs a key, sector, category and name. Optionally add the models and integrations it needs, a rule type and the objects it detects. Rows are checked first, and nothing is imported unless every row is valid.

What “Available” does and does not meanThe rules have been tested. The models themselves are not included: you install and test them on your own hardware. Most use cases also need tuning per camera (zone, thresholds, camera angle) before their alerts can be trusted. Mark the false alarms on AI events to see the false-alarm rate.

14Check the dashboards

Every device is checked every 30 seconds by default (SC_COLLECT_INTERVAL). Within a minute the dashboards fill in. Use the Showing list to look at one region, branch or floor.

Click anything for the details behind it

Every tile, bar and row on the overview opens the list behind it. Examples:

  • Cameras online lists every online camera, and Cameras offline lists the offline ones with their error message.
  • Low batteries lists the cameras below 20%, and Disk errors lists the NVRs with faulty disks.
  • A branch row lists that branch's cameras. An image-issue bar lists the cameras with that problem.
  • An alert opens the camera or NVR it is about.

A blue bar at the top shows the filter in use, with Show all to clear it.

Camera dashboard

Click any camera to open its own dashboard page:

  • status, uptime, average FPS, latency and bitrate for the period you choose (1 hour to 30 days), plus battery for battery cameras
  • charts of the same values
  • device details and the current stream and picture checks
  • its AI use cases, alert history and recent AI events

Live view opens the camera's live picture (step 15).

15Camera map and live view

Camera map

Camera map shows where each organization's cameras are. Cameras at the same place share one marker:

  • green: all of them online
  • amber: some offline
  • red: all offline

Click a marker to list its cameras, each with Live and Dashboard buttons. Use Showing to limit the map to one organization, region or branch.

Map backgroundOut of the box the map has no street background, so it works with no internet. Cameras are shown on a grid in their correct relative positions. To show streets, set SC_MAP_TILE_URL to a map tile server, for example your own or a provider you have a licence for, and SC_MAP_ATTRIBUTION to its credit line. In India, use a provider whose maps follow the official boundaries.

Live view

Click Live on the map, in Manage devices, or Live view on a camera's dashboard. The live picture opens beside the page. Closing the panel stops the stream. Every live view is recorded in the audit log, with who watched which camera.

Control live-view quality to save data

QualityPictureData per viewer (rough guide)
LowUp to 640 px wide, 5 frames per second, camera's sub-streamabout 0.3–0.6 Mbps
ModerateUp to 960 px wide, 10 frames per second, sub-streamabout 1–2 Mbps
HighUp to 1920 px wide, 15 frames per second, main streamabout 4–8 Mbps
  • For a whole organization: org admins set the highest quality their users may watch on the Locations page (organization settings). The platform admin sets it on Organizations. The default is Moderate.
  • For one camera: admins can allow a different level in the camera's live panel or its Edit form, for example High for the main gate and Low for a corridor.
  • For viewers: anyone can choose a lower level than allowed, never a higher one. Streams stop by themselves after 30 minutes (SC_LIVE_MAX_MINUTES).
  • Server load: the server shows at most 8 live streams at once (SC_MAX_LIVE_STREAMS). Live view needs FFmpeg on the server.
Not yet tried on real camerasLive view was tested with simulated cameras. With real cameras, check that the stream address and login are right (Troubleshoot helps). For many viewers at once, a media server in front of the portal is the better choice.

16Approvals

When an organization requires approval, a location admin's request to add, edit, deactivate or delete a camera or NVR is not applied straight away. It waits on the Approvals page.

  • Who can approve: someone higher up the tree, either the org admin or a location admin assigned above the requester. A branch admin's request can be approved by the regional manager.
  • Own requests: nobody can approve their own request.

17Alerts, rules and notifications

3C ITS VisionOps ships with 14 health rules. Examples: camera offline for more than 5 minutes, battery below 20%, NVR disk error, storage above 95%, recording kept for less than 7 days. A rule opens an alert when its condition has held for the set time, and closes it when the condition clears. Alert contacts are then notified as set up in step 7.

18Edge AI devices (optional)

Edge boxes such as Jetson or NUC units run AI detection near the cameras and send events to the server. Register each one under Edge devices at its location and copy its key, which is shown only once. A box can send events only for cameras at its location and below.

python -m sentinel.analytics.runner --server http://<server-ip>:8080 --api-key sc_… \
  --camera-id 12 --model yolov8n.onnx --fps 5

The box reads the camera's stream address and its use cases (step 13) from the portal, so zones and settings are managed in one place.

Not yet tested with a real modelTry the model connector on one camera before rolling it out.

19Audit log

Every sign-in, device change, approval, rejection, reboot, troubleshoot run and contact change is recorded with the user, time and IP address. Org admins and auditors see their own organization's log; the platform admin sees all of them.

20Run it as a service

On a Windows PC, use the launcher and its --install-autostart option (step 2). On a Linux server, follow the steps below.

Create /etc/sentinelcore.env, readable only by root:

SC_SECRET_KEY=paste-your-key-here
SC_DATABASE_URL=postgresql+psycopg://sentinel:DB_PASSWORD@localhost:5432/sentinel
SC_COLLECT_INTERVAL=30
SC_COOKIE_SECURE=1
SC_PUBLIC_URL=https://sentinel.yourcompany.com
SC_SMTP_HOST=mail.yourcompany.com
SC_SMTP_USER=sentinel@yourcompany.com
SC_SMTP_PASSWORD=your-mail-password
SC_SMTP_FROM=sentinel@yourcompany.com
SC_SMS_URL=https://your-sms-provider.example/api/send
SC_SMS_HEADERS={"Authorization": "Bearer your-api-key"}
# Optional: street background for the camera map, live-view limits
SC_MAP_TILE_URL=https://tiles.yourcompany.local/{z}/{x}/{y}.png
SC_MAP_ATTRIBUTION=Map data © your provider
SC_MAX_LIVE_STREAMS=8
SC_LIVE_MAX_MINUTES=30

Then create /etc/systemd/system/sentinelcore.service, changing /opt/bhat to where you cloned the code:

[Unit]
Description=3C ITS VisionOps
After=network-online.target postgresql.service

[Service]
WorkingDirectory=/opt/bhat/sentinelcore
EnvironmentFile=/etc/sentinelcore.env
ExecStart=/opt/bhat/sentinelcore/.venv/bin/uvicorn sentinel.main:app --host 127.0.0.1 --port 8080 --proxy-headers
Restart=always
User=sentinel

[Install]
WantedBy=multi-user.target
sudo useradd -r sentinel
sudo systemctl daemon-reload
sudo systemctl enable --now sentinelcore
sudo journalctl -u sentinelcore -f

Put nginx or Caddy in front of it with a certificate from your internal certificate authority, so users connect over HTTPS.

21Go-live checklist

  • SC_SECRET_KEY is set and backed up somewhere safe
  • The admin password has been changed from the generated one
  • PostgreSQL is used, with a nightly pg_dump backup
  • Users connect over HTTPS, and SC_COOKIE_SECURE=1 is set
  • Each organization's location tree matches its real branches and offices
  • Each user has the lowest role and fewest locations they need
  • Approval is on for organizations that require sign-off on device changes
  • Every branch has at least one alert contact, and escalation contacts are set for regions
  • Send test reaches each contact by email and SMS
  • No device still uses the simulator driver: the SIMULATED DATA badge is gone
  • For 10 devices, make, model, serial number and health match the device's own web page
  • Troubleshoot passes on a known-good camera; reboot tested on one camera and one NVR
  • Unplugging one test camera opens a “Camera offline > 5 min” alert and the branch contact is notified

22Troubleshooting

Start with the device's Troubleshoot button. It names the failing check and what to do. Common cases:

SymptomLikely cause and fix
Offline with “connect failed”The server cannot reach the device. Run nc -vz <ip> 554 from the server; check routing, VLAN and firewall to that branch
“The device refused the ONVIF login”Many cameras need a separate ONVIF user. On Hikvision: Configuration → Network → Advanced → Integration Protocol
Make, model or serial says “Not detected yet”Set the camera's IP address and ONVIF login, or switch an NVR to the onvif or hikvision_isapi driver
NVR disks read “Not supported”Use hikvision_isapi, after testing curl --digest -u admin:PASS http://NVR/ISAPI/ContentMgmt/Storage
Reboot failsCheck the user has ONVIF admin rights; for cameras behind an NVR with no own IP, reboot the NVR
Notifications “skipped”SC_SMTP_HOST or SC_SMS_URL is not set (step 7)
Notifications “failed”Read the error in the Notification log: wrong mail login, blocked port, or wrong SMS gateway format
A branch admin's change did not appearThe organization requires approval; look on Approvals
CSV row: “matches 2 locations”Two locations share that name; use the location code or full path
VisionOps stopped or froze while running in a PowerShell windowSomeone clicked inside the window (Windows pauses it), or the window was closed. Start with start-visionops.bat instead (step 2); it runs in the background and restarts itself
The launcher says “stopped several times in a row”Something stops it at start-up. The launcher shows the last lines of logs\server-output.log; send that file to support
Browser shows “This site can’t be reached” at localhost:8080The portal is not running. Start it again in PowerShell and keep that window open until you see Uvicorn running on http://127.0.0.1:8080. Use http://, not https://
Page looks like the old version after an updatePress Ctrl+F5 once. From v0.3.2 the portal tells browsers to check for new files, so this should not happen again
All stored device passwords stopped workingSC_SECRET_KEY changed. Restore the original key, or enter the passwords again
