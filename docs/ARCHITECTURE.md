# 3C IT Solutions LMS: Architecture

This document describes how the LMS for 3C IT Solutions and Telecoms India Ltd is built and deployed. It also lists the assumptions made and the questions the company still needs to answer. The detailed design history is in `docs/superpowers/specs/`.

## 1. Overview

```
 Browser (LAN / VPN)
        │  HTTPS (internal CA certificate)
        ▼
 ┌──────────────┐     ┌───────────────────────────────┐     ┌──────────────┐
 │ Nginx        │────▶│ Next.js app × 3 replicas       │────▶│ PostgreSQL 16│
 │ TLS, gzip,   │     │  • pages for /admin /manager   │     └──────────────┘
 │ upload limit │     │    /learn (React server        │            ▲
 └──────────────┘     │    components)                 │            │ pg_dump
                      │  • server actions + API routes │     ┌──────┴───────┐
                      │  • role and scope checks       │     │ backup       │
                      │  • local file storage ─────────┼────▶│ (daily,      │
                      └───────────────┬───────────────┘     │ encrypted)   │
                                      │                      └──────────────┘
                      ┌───────────────┴───────────────┐
                      │ scheduler (hourly): opens      │
                      │ periods, marks overdue, sends  │
                      │ reminders via company SMTP     │
                      └───────────────────────────────┘
```

All containers run from Docker Compose on one server. No container reaches the internet at runtime: fonts are system fonts, charts and PDFs are generated by bundled libraries, and QR codes are drawn by the server.

## 2. Technology choices

| Concern | Choice | Why |
| --- | --- | --- |
| Backend and frontend | One Next.js 16 app in TypeScript (App Router, server actions) | One language and one deployable unit. The brief allows Node.js with React or Next.js. |
| Database | PostgreSQL 16 through Prisma 7 | Required by the brief. Prisma gives typed queries and versioned migrations. |
| Passwords | bcrypt (cost 12) | Required by the brief. |
| Sessions | Random token in an HTTP-only, SameSite=Lax, Secure cookie. Only its SHA-256 is stored in Postgres. A session ends after 30 idle minutes (`SESSION_IDLE_MINUTES`) or 12 hours, whichever comes first. | The server can revoke it. Deactivated users are signed out on their next request. |
| CSRF | Next.js server actions check the request origin. State-changing API routes accept POST only and need the session cookie, which is SameSite. | |
| File storage | Local disk outside the web root, served through routes that check access. Video is streamed with HTTP range requests. | No external service. A MinIO/S3 implementation can sit behind the same interface (`src/lib/storage/types.ts`). |
| PDFs | pdf-lib (certificates) | Pure JavaScript, no internet. |
| Charts | Recharts | Bundled with the app. |
| Email | nodemailer to the company SMTP server | |
| Tests | Vitest (unit and integration, against a real Postgres), Playwright (end-to-end), axe-core (accessibility) | |
| Reverse proxy | Nginx with TLS | Required by the brief. |

## 4. Data model (summary)

- **Organisation:** `users` (role ADMIN / MANAGER / EMPLOYEE, department, job title, location, manager_id). Departments, job titles and locations are values on the user, so an import can create them. Managers see their whole reporting line (direct and indirect).
- **Catalogue:** `subjects` → `courses` (level BASIC / INTERMEDIATE / ADVANCED, status DRAFT / PUBLISHED / ARCHIVED) → `modules` → `lessons` (TEXT, PDF, VIDEO, LINK, LIVE_SESSION, LAB).
- **Enrolment:** `course_assignments` (to a USER, DEPARTMENT or JOB_TITLE, with an optional due date; department and job title resolve when read, so later joiners are enrolled automatically). Learners can also start any published course themselves.
- **Progress:** `course_progress` (completed lessons, last lesson) and `lesson_progress` (video position, lab checklist).
- **Assessments:** `assessments` (cadence ONE_TIME / WEEKLY / MONTHLY / ANNUAL, pass mark, time limit, attempts, pool size, retake delay, proctored mode) → `questions` (SINGLE, MULTIPLE, TRUE_FALSE, FILL_BLANK, MATCHING, SHORT_ANSWER, each with an optional scenario and explanation). `assessment_assignments` target everyone, a department, or a user. `assessment_periods` hold one row per user per period, and `assessment_attempts` hold each attempt with its answers, reviewer marks, and proctoring events. Attempts with short answers wait as AWAITING_GRADING.
- **Remedial path:** `remedial_plans` (opened on a fail: the linked course is redone, and the retake opens after a delay; managers comment).
- **Certification:** `certifications` with a 12-character verification code, a QR code on the PDF, and an expiry date (default 12 months, set per subject).
- **Community:** `announcements`, `course_feedback` (end-of-course survey), `course_posts` (Q&A, moderated).
- **Operations:** `notifications` (each reminder sent once), `audit_events` (append-only), `sessions`, `login_failures` (sign-in rate limit).

## 5. Security

- Every page and server action checks the role and, for managers, the reporting line on the server (`src/lib/auth/guards.ts`). The UI hiding a button is never the only check.
- Prisma uses parameterised queries, so user input never builds SQL.
- React escapes output. Lesson text is shown as plain text, so it cannot carry HTML or script.
- Sign-in is rate-limited: 5 failures per email or 30 per IP address in 15 minutes block further tries (`src/lib/auth/rate-limit.ts`).
- Sessions end after 30 idle minutes or 12 hours.
- Uploaded files are checked for type and size, stored under random names, and served only to users who can see the course.
- Backups are encrypted with AES-256 (GPG symmetric) before they are written.
- The audit log has no update or delete path in the app.

## 6. Sizing (300 concurrent users)

The target server is 8 vCPU, 16 GB RAM, and SSD storage.

| Item | Assumption or measurement |
| --- | --- |
| Concurrent users | 300 signed in. A busy user opens a page about every 10 seconds, so about 30 page requests per second. |
| App | One Node.js process uses one core and handles about 70 page requests per second on the test machine (4 vCPU). Production runs 3 replicas (`APP_REPLICAS`) behind Nginx, leaving cores for PostgreSQL, Nginx and the OS. Measured on the 4 vCPU test machine through Nginx with 3 replicas: 300 connections at 90 requests per second (three times the expected load), no errors, median 203 ms, 99th percentile 870 ms. See `TESTING.md` section 4. |
| Database | PostgreSQL with `shared_buffers` 4 GB, `effective_cache_size` 10 GB and `max_connections` 100. Each app process pools 10 connections. Typical page queries take 1–5 ms. |
| Video | A 720p MP4 at about 2.5 Mbps. 40 simultaneous viewers need about 100 Mbps, so a 1 Gbps LAN link carries about 300 viewers. Video is served with byte ranges, so seeking does not re-download. |
| Storage | About 200 MB per hour of 720p video. Budget 200 GB for content and 3× the database size for 14 days of backups. |
| Page load | Under 2 seconds on the LAN: pages are server-rendered, each takes 10–25 ms to render unloaded, and the static shell and scripts are cached. |

Phase 4 must repeat the load test on the production server with real data.

## 7. Assumptions

1. Learners are company employees only. There is no multi-tenancy and no external learners.
2. Departments and locations are free-text values on the user record, created by the admin or by import. There is no separate approval hierarchy beyond the reporting manager.
3. The company provides an internal CA certificate, or accepts the self-signed certificate created by `deploy/nginx/make-cert.sh`.
4. The company SMTP server accepts mail from the LMS server without OAuth.
5. One weekly assessment runs per assigned subject, and it opens on Monday (ISO week). The weekday can be changed in configuration.
6. Certificates are valid for 12 months unless a subject sets a different validity.
7. Correct answers are hidden after submission unless the admin enables them per assessment.
8. Proctored mode is a deterrent, not a guarantee. It records full-screen exits and tab switches, and can submit the attempt automatically after a set number of violations. It cannot stop a second device.
9. All course content in this repository is a placeholder. The company supplies the real videos, documents, and SCORM packages, and approves all wording about policies, prices, and products.
